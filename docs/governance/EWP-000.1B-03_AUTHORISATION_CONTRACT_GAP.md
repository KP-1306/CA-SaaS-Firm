# EWP-000.1B-03 — Authorisation Contract Gap Record

**Status:** BLOCKED_PENDING_CANONICAL_CONTRACT
**Classification:** Governance evidence only
**Implementation authorised:** NO
**Architecture invention permitted:** NO

## Purpose

This record documents the due-diligence result obtained before beginning
EWP-000.1B-03 authorisation-context implementation.

It does not define, redesign or implement authorisation behaviour.

## Repository evidence recovered

The repository establishes only the following high-level constraints:

1. The application contains structurally separate internal, portal and platform planes.
2. Internal users are represented by an internal principal.
3. Portal users require a portal principal with active organisation membership.
4. Platform users require a platform principal operating under a time-boxed,
   tenant-approved support grant.
5. Portal principals cannot hold internal permissions.
6. The architecture refers to an authorisation context.
7. The architecture refers to a five-layer authorisation decision.
8. Authentication, session handling, tenant isolation, row-level security and
   authorisation are explicitly recorded as later work and are not implemented.

## Decision

would require inventing security architecture.

EWP-000.1B-03 remains blocked until one of the following occurs:

1. the original canonical contract is supplied and recovered; or
2. a replacement contract is explicitly designed, reviewed, approved and frozen
   through the agreed governance lifecycle.
